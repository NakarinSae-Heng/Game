# PAC RUSH 🟡

เกม Pac-Man สำหรับมือถือ เขียนด้วย HTML5 Canvas + JavaScript ล้วน ไม่มี build step
ไม่มี dependency และไม่มีไฟล์ asset ภายนอกเลย — กราฟิกวาดด้วย Canvas ทั้งหมด
เสียงสังเคราะห์ด้วย WebAudio ทั้งหมด จึงโหลดไว ติดตั้งลงหน้าจอโฮมได้ และเล่นออฟไลน์ได้

## เล่นเลย

ต้องเปิดผ่าน HTTP (ES modules และ service worker ใช้ `file://` ไม่ได้):

```bash
python3 -m http.server 8000
# แล้วเปิด http://localhost:8000
```

เปิดจากมือถือในวง Wi-Fi เดียวกัน: `http://<ip-เครื่อง>:8000`
หรือเปิด GitHub Pages ให้ repo นี้ (Settings → Pages → branch นี้, folder `/`)
แล้วกด "เพิ่มไปยังหน้าจอโฮม" เพื่อเล่นแบบเต็มจอเหมือนแอป

## การควบคุม

| วิธี | รายละเอียด |
|---|---|
| **ปัดนิ้ว** | ปัดที่ไหนก็ได้บนจอ (ยกเว้นตัวปุ่ม) เปลี่ยนทิศทันทีที่ปัดเกิน 24px ไม่ต้องยกนิ้ว |
| **D-pad** | ปุ่มโปร่งแสงครึ่งล่าง อยู่ในระยะนิ้วโป้ง กดค้างเพื่อสั่งทิศซ้ำ ลากนิ้วข้ามปุ่มได้ |
| **คีย์บอร์ด** | ลูกศร / WASD / HJKL, `Space` `Esc` `P` = หยุดพัก |

สั่งเลี้ยวล่วงหน้าก่อนถึงทางแยกได้เลย เกมจะจำทิศไว้ ~0.45 วินาที
แล้วเลี้ยวให้พอดีตอนถึงทางแยก และยังตัดมุมได้เหมือนต้นฉบับ

## ลูกเล่นในเกม

- **6 ด่าน** ออกแบบมือ วนซ้ำเมื่อจบ ยากขึ้นเรื่อยๆ ทุกด่าน
- **ผี 4 ตัวมีบุคลิกต่างกัน** — บลิงกี้ไล่ตรงๆ · พิงกี้ดักหน้า · อิงกี้เล็งจุดสะท้อน
  (คาดเดายากที่สุด) · ไคลด์ไล่ตอนไกลแต่ถอยตอนใกล้
- **ผีฉลาดขึ้นตามด่าน** — เร็วขึ้น, พิงกี้ดักไกลขึ้น, เวลาโหมดกลัวสั้นลง
  และ **Cruise Elroy**: บลิงกี้จะเร็วขึ้นและเลิก scatter เมื่อเม็ดถั่วเหลือน้อย
- **Power-up 6 แบบ** — ⏳ ผีอืด · 🧲 ดูดเม็ดถั่ว · 🛡️ กันตาย 1 ครั้ง ·
  ❄️ แช่แข็งผี · ✨ คะแนนคูณสอง · ⚡ วิ่งไว (มีแถบนับเวลาบน HUD, ซ้อนกันได้)
- **คอมโบ** กินต่อเนื่องเร็วๆ ได้ตัวคูณถึง x10
- **Juice** — ประกายไฟ, จอสั่น, สโลโมชันตอนกินผี, แฟลช, และสั่นเครื่อง (ปิดได้)
- **ภารกิจรายวัน** 3 ข้อ สุ่มจากวันที่ ทุกเครื่องได้ชุดเดียวกัน ทำได้รับเหรียญ → ปลดสกิน
- **ตารางคะแนน** 10 อันดับในเครื่อง
- อุโมงค์ซ้าย-ขวาทะลุถึงกัน และผีวิ่งช้าลงในอุโมงค์

## โครงสร้างโค้ด

```
index.html                 หน้าเดียว: canvas + HUD + ปุ่ม + หน้าจอซ้อน
css/style.css              layout เน้นมือถือ (safe-area, D-pad, แนวตั้ง/แนวนอน)
manifest.webmanifest, sw.js   PWA: ติดตั้งได้ + เล่นออฟไลน์
js/
  main.js         ลูปเกม fixed timestep, ขนาด canvas, ต่อสายทุกระบบ
  config.js       ค่าปรับจูนทั้งหมดอยู่ที่นี่ที่เดียว
  game.js         กฎการเล่นทั้งหมด (กิน, ชนผี, ขึ้นด่าน, คะแนน)
  maze.js         เมซ 6 ด่าน + parser
  mazeRenderer.js วาดกำแพงลง canvas สำรองครั้งเดียวต่อด่าน
  render.js       วาดสิ่งที่เปลี่ยนทุกเฟรม
  movement.js     การเดินบนกริดแบบต่อเนื่อง (หัวใจของฟีลลิ่งการบังคับ)
  entities/       pacman.js, ghost.js
  ghostAI.js      เป้าหมายตามบุคลิก + การเลือกทางแยก
  powerups.js  combo.js  fx.js  audio.js  input.js
  hud.js  ui.js  storage.js  missions.js  leaderboard.js
tools/validate-mazes.mjs   ตรวจเมซทุกด่าน
```

### จุดที่ออกแบบไว้เป็นพิเศษ

**เมซเขียนเป็นครึ่งซ้าย** กว้าง 14 ช่อง แล้ว parser mirror ให้เป็น 28×31
ทำให้เมซสมมาตรสวยงามและงานเขียนลดลงครึ่งหนึ่ง จากนั้น parser จะ **ปั๊มบ้านผี
อุโมงค์ และทางเดินรอบบ้านผี** ลงไปเหมือนกันทุกด่าน แล้ว **flood fill จากจุดเกิด
ผู้เล่นและปิดทุกช่องที่เดินไปไม่ถึง** — ด่านจึงเก็บครบได้เสมอ แม้เขียนเมซพลาด

**การเดินยึดกฎเดียว**: เดินแนวนอน → `y` เป็นจำนวนเต็มเสมอ, เดินแนวตั้ง → `x`
เป็นจำนวนเต็มเสมอ และตัวละครจะหยุดที่กลางช่องทุกครั้งที่ผ่าน ทำให้การตรวจกำแพง
และการตัดสินใจของผีแม่นยำ ไม่มีทางหลุดเข้าไปในกำแพง

**เอฟเฟกต์เดินด้วยเวลาจริง** ส่วนการเล่นเดินด้วยเวลาที่ถูกปรับด้วยสโลโมชัน
ภาพจึงลื่นตลอดแม้ตอนที่เกมช้าลงหลังกินผี

## ตรวจสอบ

```bash
node tools/validate-mazes.mjs          # ตรวจเมซ: mirror, จำนวนเม็ด, การเดินถึง, ทางตัน
node tools/validate-mazes.mjs --print  # พิมพ์ผังเมซออกมาดู
```

เปิดด้วย `?debug=1` เพื่อดู FPS, โหมด scatter/chase, จำนวนเม็ดที่เหลือ,
ขั้น Elroy, ทางแยก และเส้นเป้าหมายของผีแต่ละตัว

ที่ทดสอบไว้แล้วบนเบราว์เซอร์จริง (Chromium ขนาดจอมือถือ): เมนู → เล่น → ปัดนิ้ว
และ D-pad ทั้งสี่ทิศ → กิน power pellet → กินผีได้ 200/400/800/1600 →
ผีกลับเข้าบ้านและออกมาใหม่ → power-up ทั้ง 6 แบบ → ผลไม้ → เกราะ → ตายจนจบเกม →
บันทึกคะแนน → ขึ้นด่านใหม่ครบทั้ง 6 เมซ, ไม่มี error ใน console,
เฟรมละ ~16.7ms (60fps) และ layout พอดีจอตั้งแต่ 375×553 ถึง iPad ทั้งแนวตั้งและแนวนอน

## หมายเหตุ

- ไม่มี unit test framework เพราะโปรเจกต์ไม่มี build step และ logic ผูกกับการวาดภาพ
  จึงใช้ maze validator + การขับเกมจริงในเบราว์เซอร์แทน
- คะแนนและภารกิจเก็บใน `localStorage` ของเครื่อง ไม่มีเซิร์ฟเวอร์ ไม่ต้องล็อกอิน
- เกมเคารพ `prefers-reduced-motion` (ลดการสั่นและแฟลชให้เอง)
